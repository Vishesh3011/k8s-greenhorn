# Resources used by Kubernetes to deploy applications
In this module, we will cover the various resources used by Kubernetes to deploy applications. We will also provide yaml examples for each resource type.
1. [Pod](pods/README.md) : A pod is the smallest and simplest Kubernetes object. It represents a single instance of a running process in a cluster. A pod can contain one or more containers, which are co-located and share resources. Pods are ephemeral and can be created, destroyed, and recreated as needed.
2. [Deployment](deployments/README.md) : A deployment is a higher-level Kubernetes object that manages a set of replicas of a pod. It provides declarative updates for pods and replica sets. A deployment ensures that a specified number of pod replicas are running at any given time. It also provides features like rolling updates and rollbacks.
3. [Service](services/README.md) : A service is a Kubernetes object that provides a stable network identity (IP and DNS) to a set of pods. It acts as a load balancer and routes traffic to the pods. It also provides service discovery for the pods. Services can be exposed to external traffic using different types of services like NodePort, LoadBalancer and ClusterIP.
4. [Ingress](ingress/README.md) : An ingress is a Kubernetes object that manages external access to the services in a cluster, typically HTTP. It provides features like load balancing, SSL termination, and name-based virtual hosting. An ingress controller is responsible for fulfilling the ingress, usually with a load balancer, though it may also configure your edge router or additional frontends to help handling the traffic.
5. ConfigMap and Secret : ConfigMap and Secret are Kubernetes objects that are used to store configuration data and sensitive information respectively. They can be used to decouple configuration from the application code and provide a way to manage configuration data in a centralized manner.
6. Namespace : A namespace is a Kubernetes object that provides a way to divide cluster resources between multiple users. It allows you to create multiple virtual clusters within a single physical cluster. Each namespace has its own set of resources and can be used to isolate different teams or projects within the same cluster.
7. StatefulSet : A StatefulSet is a Kubernetes object that manages the deployment and scaling of a set of pods, and provides guarantees about the ordering and uniqueness of these pods. It is used for stateful applications that require stable network identities and persistent storage.
